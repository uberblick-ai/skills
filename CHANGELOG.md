# Changelog

## Unreleased

- `ci-health` 1.5: a "Failed runs" chart with the share of run attempts on the default branch that ended red, per day and pooled over 7 days. Every attempt counts, so a red run re-run green reads as 1 of 2; `collect` reads earlier attempts of re-run runs, one call each. Cancelled and skipped attempts count in neither part, and with `--workflow` only the named workflows' runs count. The day's `runs`, `failure_pct` and `failure_pct_7d` are stored with the other figures and appear in the summary table.
- `ub-agents-deliver-report` 1.3: the same for its Recommended Actions. The prompt has the discussing session strike the card through with the pull request or issue as a GitHub pill and set the lesson to `tracked` with `addressed_by` and the new `addressed_as` (`implemented` or `planned`). `document` lists the `tracked` lessons of the last 14 days below the proposed ones, struck through, until their change merges or closes, and marks them `struck` so the skill replaces rather than edits them.
- `ci-health` 1.4: when the discussion an action card opens settles on applying the action, its prompt has that session strike the card's title and why through, drop the button and add a footer, not struck through, naming the pull request that implements it or the issue that plans it as a GitHub pill. It also stores the decision in a separate `applied` collection, so `cards --applied` keeps the card struck through on later runs, the action keeps its place until that pull request or issue is merged or closed, and `records --applied` deletes the marks of dropped actions.
- Each skill page on skills.uberblick.ai and `skills.md` show the command that updates an installed skill, for a project or a global install, since an installed copy keeps its version until updated.
- `ub-agents-deliver-report` 1.2: `collect` adds evidence to every item that needs a cause (commits pushed outside any run, label and state changes by people, CI runs on its PRs), and `digest` prints the day in a few lines per item for the agent to read instead of `data.json`. `records` leaves collection schemas out unless `--schemas` is passed and prints compact JSON, about half the batch the agent passes to `update_data`. `document` marks the action cards the day changed and counts the new changelog items, so the agent updates the document block by block, editing a changed card in place; a card's prompt carries its lesson's day. Autonomous deliveries (75% or more), wasted runs and runs with denials (under 10% each) get targets on the page, in the digest and in a new document's KPI table, and a new document's Recent days table shows the newest seven days.
- `ub-agents-unblock` 0.5: each summary and question opens with the item's full GitHub URL, and each question with one plain sentence on what the item is and what it changes for users, so the prompt makes sense without the summary above it. Its skills.uberblick.ai page now says what each question shows.
- Add `ub-agents-unblock` 0.4 under `skills/ub-agents/`: first learns how the repository runs its loop from `ub-agents.yaml` and the agent instruction files (the local checkout, or GitHub without one), then lists parked, blocked and failed items from `ub-agents status --json` with their Action needed notices (falling back to `gh api` for items with a stop label), highest priority and longest waiting first, and takes them one at a time. For each it recommends a decision from the item and the repository's agent guidance (`AGENTS.md`, shared and role instructions, `ub-agents.yaml`) and asks with an interactive prompt; a short section explains triggers, outcomes, stop labels and approvals. The maintainer picks an option, answers, merges, closes or skips; the skill says what it will change, then posts the answer and swaps the stop label for the trigger the notice names, merges only at the notice's SHA, or closes. Its own GitHub calls are REST `gh api`, so the fallback also runs where GraphQL is unavailable.
- `ub-agents-deliver-report` 1.1 and `ci-health` 1.3: action cards carry a "Discuss in Claude Code" button that opens a new session in the Claude desktop app with a prompt to discuss the action before changing anything. The delivery report's actions become cards under a "Recommended Actions" heading, like ci-health's: the lever as the label, the title, the change as the body, and where it lives, its cost, causes and evidence in the footer; `document --doc DOC` names the document in the prompt. ci-health's link moves from the footer, where Uberblick takes only http(s) links and so never showed it, to a `button:` line. Uberblick reads card buttons from the release after 0.4.3; with 0.4.3, `--no-button` on `document`, `create` and `cards` leaves the button out.
- `ci-health` 1.2: the report keeps the top three actions that would most cut the time pushes wait for a green main, judged again on every run over the last days rather than the collected day alone. `ci.py signals` gives the evidence for the 7 days ending the last day (the job that ends last and by how much, failures by job, runner waits, hangs) with a rough count of the minutes of waiting a day each accounts for, so actions rank on one scale. The agent keeps an action while its evidence holds, drops one that is done or no longer shows, and replaces one only when a candidate saves clearly more. Actions are stored in an `actions` collection, keeping their `since`, and `ci.py cards` renders them as cards under a "Recommended Actions" heading between the charts and the incidents, each with a "Discuss in Claude Code" link that opens a new session in the Claude desktop app (`claude://code/new`) with a prompt to discuss the action before changing anything.
- `ci-health` 1.1: `measure` counts lines with scc, or cloc without it, instead of non-blank lines by file extension. Both tell comments from code in every language they know, so a comment cleanup no longer reads as less code, and the count no longer depends on a list of languages; prose and data (Markdown, text, JSON, YAML and the like) stay out. The agent chooses the main source directories from the repository's layout and passes them as git pathspecs with `--path`; only files git tracks count, so dependencies, build output and nested worktrees never do. Days record `loc_tool` and `loc_paths`. Without a counter or a `mise run loc` task, `measure` says so once, suggests the install command for the host's package manager, and leaves the ratio out. Days measured with 1.0 counted comments and every directory; remeasure them with `measure --every-day` to keep the ratio comparable.
- Add `ci-health` 1.0 in the `maintenance` group, for any repository and language: CI on the default branch from GitHub Actions, one record per UTC day with the median wall time of green pushes (first job start to last job end, over every workflow of the push), a 7-day median as the headline with its ± spread and P95, each job's median in the data to explain steps, execution minutes and runner waits for contrast, and failed pushes. The agent reads the test count off the job logs with patterns it writes for the repository's runners (`logs`, `tests --pattern`). `measure` adds the test-to-code line ratio, and coverage when the checkout defines `mise run codecov` (`mise run loc` replaces the built-in line count). `shifts` proposes steps in wall time and stretches of hung runs; the agent names the change behind each and stores it as an incident. With the Uberblick MCP tools or the `ub` command (`ci.py ub` calls tools through one `ub mcp serve` and waits for the hub to acknowledge writes), `create`, `records`, `charts` and `changelog` keep one "CI Health Report" document per repository: intent, charts bound to its `days`, and below them the latest five incidents, with a description and catalog tags and no TL;DR.
- Add the website at skills.uberblick.ai: `site/build.py` builds an overview and one page per skill from the `SKILL.md` files, group READMEs and marketplace, plus `skills.md`, `llms.txt`, a sitemap and a 404 page. Optional `site/content/skills/<name>.json` adds example asks, steps and report screenshots. CI builds the site on every change.
- Add `backlog-grooming` 1.1 in the new `maintenance` group: repository, milestone and project review, bounded independent challenges, chat decisions, optional ub-agents eligibility, and a reusable HTML/JSON decision report. Independent portability review removed the medium-as-default assumption and added visibly identified drafts without required permalinks.

- Add `ub-agents-deliver-report` under `skills/ub-agents/`, the `delivery-review` skill moved out of uberblick-2 and ub-agents; one script now serves both role setups. Compared with the source copies: the window is a calendar day in local time instead of the last 24 hours, the page is defined in `references/report.md`, `render` opens the report in the default browser, and the slides are gone. It measures the KPIs the loop is steered by (autonomous deliveries, wasted runs, human stops and the wait for them, cycle without that wait, run time, runs with permission denials), classifies runs from each role's outcomes and triggers in `ub-agents.yaml`, names findings from a cause registry with a fixed class list so recurrence is visible, groups the day's retrospectives by cause, and `records` turns a day into an `update_data` batch for an Uberblick document's `days`, `items`, `findings`, `causes`, `lessons` and `changes`. Recent days is a data-backed table block in that document, and `document` renders its top five open actions and a short changelog of the latest changes; a lesson leaves the actions once an issue or PR addresses it, or after 14 days without new evidence. Item detail is kept compact, one record per day, for 14 days; daily figures and findings stay for long-term trends. The document is optional: the skill updates it when it exists, offers to create it (`create` writes the `create_doc` arguments) when Uberblick is available but no document holds the data, and skips it when Uberblick is not available. Collection reads comments only for items opened before the day ended that have any, and PR sizes only for PRs merged that day, so a day costs about 140 GitHub API calls and backfilling an older day no longer pays for everything touched since. Skills under `skills/` install with `npx skills@latest add uberblick-ai/skills`.
- Remove the `/uberblick` plugin; the last version that carried it is the commit before this change. The `uberblick-ai` marketplace stays and now lists one plugin per skill group, `ub-agents` first, pointing at the skills in place; `scripts/check_marketplace.py` keeps it in step with `skills/`.
